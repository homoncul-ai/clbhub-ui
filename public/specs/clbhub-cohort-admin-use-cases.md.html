[← Specs index](./) # CLBHub Cohort Admin Use Cases ## Purpose This document extracts **admin-facing use cases** for cohort management in CLBHub. It consolidates requirements from: 1. **[clbhub-cohort-experience-model.md](./clbhub-cohort-experience-model.md.html)** — cohort-side `CohortExperience` and `CohortExperienceParticipant` behavior. 2. **Provider dashboard cohort UI wireframe** — `trutesta-hccl-mdb5-ui/src/app/features/dash-provider/cohorts/` (`cohort-leader-ui-example`, `cohort-mvp-documentation.ts`). Admin actors include **Cohort Leader**, **Facilitator**, and other **authorized provider users**. Sponsor-facing read-only views are included where the wireframe treats them as a distinct admin persona. ## Origin key | Origin | Meaning | | -------- | -------------------------------------------------------------------------------------- | | **Spec** | Derived from `clbhub-cohort-experience-model.md` only | | **UI** | Shown or documented in the provider-dash cohort wireframe only | | **Both** | Present in the experience model and represented (or closely mirrored) in the wireframe | UI references use the wireframe **tab**, **panel title**, and `docId` from `cohort-mvp-documentation.ts` where applicable. **C-01 – C-08, C-10** — full `CohortExperience` / `CohortExperienceParticipant` CRUD - **C-03, C-04, C-05, C-06** — cohort-specific title, description, importance, roundtable flag - **F-09, F-10** — roundtable completion monitoring and progress evidence (detailed roundtable UX TBD) - **I-05** — sponsorship field on experience participation (wireframe has sponsor contributions, not per-experience participant sponsorship) ### UI-only (not in experience model spec) The wireframe describes broader cohort MVP admin scope: - **A-01 – A-07** — cohort creation & configuration - **B-01 – B-07** — enrollment & onboarding flows - **D-01 – D-05** — seminar program builder & resource library - **E-01 – E-05** — book club communication - **F-01 – F-08** — goals, hours, nudges, check-ins, 1:1 messaging - **G-01 – G-05** — leader dashboard & operational tools - **H-01 – H-03** — consent matrix & audit - **I-01 – I-04** — sponsor read-only/contribution views - **J-01 – J-04** — notifications & leader alerts - **K-01 – K-04** — reporting & heatmap ### Both (conceptual overlap) | Topic | Spec | UI | | ------------------------------------- | ------------------------------------------------- | ------------------------------------------------------- | | Cohort calendar presentation | C-09 calendar fields for CohortExperience | Weekly opportunities, internal events, program schedule | | Post-activity structured follow-up | Roundtable requirement & completion tracking | Reflection wall, check-ins, nudges | | Sponsor relationship to participation | `sponsoredByOrgId` on CohortExperienceParticipant | Sponsor contributions & impact report | | Leader visibility into engagement | Roundtable / participant follow-up outcomes | Dashboard, at-risk list, attendance, read receipts | --- ## Open admin decisions (from spec) These affect admin UX but remain TBD in `clbhub-cohort-experience-model.md`: -
