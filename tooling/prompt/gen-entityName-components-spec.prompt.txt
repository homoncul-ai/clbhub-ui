# AI Component Generation Spec Template

## Preamble: AI Mindset and Goals

You are an expert Angular developer and code generator. Your task is to generate a clear, maintainable, and **idempotent** specification for a set of three Angular components (CRUD, List, Group) for a given `entityName`. This spec will be used as the source of truth for generating and **re-generating** these components, ensuring that updates to the spec can be safely and efficiently propagated to the codebase.

- **Be precise and unambiguous.**
- **Favor clarity and maintainability.**
- **Assume the spec may be updated and re-applied multiple times.**
- **Do not generate code directly; generate a markdown spec that describes the code to be generated.**
- **Reference working examples and best practices from the project.**
- **All generated files must be idempotent: re-running the generator with an updated spec should not break or duplicate code.**

---

## Output

- The output is a markdown spec file: `src/app/components/_crud/[entityName]/[entityName]-gencomp.prompt.txt`.
- This spec will be reviewed and possibly edited before actual code generation.
- The spec will be used to generate or update the following components:
  - CRUD Component
  - List Component
  - Group Component

---

## General Guidelines

- All component files reside in `src/app/components/_crud/[entityName]`.
- Do **not** create subfolders for each component.
- All components use the global SCSS file; local `.scss` files should be empty.
- Components must call the appropriate methods in `HcclService` for the given entity.
- Use and reference working examples from the project (e.g., CLStudent components).
- The spec should be easy to update and re-apply for future changes.

---

# Component Specification Structure

## CRUD Component
- **Purpose:** Display, edit, and add `[entityName]` data.
- **Files:**
  - `[entityName]-crud.component.html`
  - `[entityName]-crud.component.ts`
  - `[entityName]-crud.component.scss` (empty)

### Section: Details
- **Based on:** `HcclService` interface `[entityName]GETData`
- **Method call:** `this.hcclService.get[entityName]ById(id)`
- **Attributes Table:**
  - List all attributes in tabular format.
  - `id` always first; audit fields (`createdByInfo`, `dateCreated`, `lastUpdatedByInfo`, `dateLastUpdated`) always last.
  - For each field, specify: `attrName`, `type`, `label`, and any special display hint (e.g., use `<app-dategetdata-display>` for dates).
  - For EFK triplets (`[prefix]EntityId`, `[prefix]EntityType`, `[prefix]EntityName`), use `<app-efk-display ...>`.
  - For foreign keys (`[prefix]Id`), use `<app-[fkEntityName]-crud ... mode="CrudModes.FK">`.

### Section: Edit
- **Based on:** `HcclService` interface `[entityName]PUTData`
- **Method call:** `this.hcclService.update[entityName]ById(id, body)`
- **Attributes Table:**
  - List all editable attributes in tabular format.
  - For each field, specify: `attrName`, `type`, `label`, and any special display hint (e.g., dropdown, date picker, textarea).

### Section: Add
- **Based on:** `HcclService` interface `[entityName]POSTData`
- **Method call:** `this.hcclService.create[entityName](body)`
- **Attributes Table:**
  - List all addable attributes in tabular format.
  - For each field, specify: `attrName`, `type`, `label`, and any special display hint (e.g., dropdown, date picker, textarea).

## List Component
- **Purpose:** Router target to search and list `[entityName]GETData`.
- **Files:**
  - `[entityName]-list.component.html`
  - `[entityName]-list.component.ts`
  - `[entityName]-list.component.scss` (empty)
- **Reference:** Base on the `CLStudentList` component.
- **Method call:** `this.hcclService.find[entityName]s(criteria)`
- **Attributes Table:**
  - Show a table of the GETData attributes, just like for Details.

## Notes for Future Updates
- This spec is designed to be **idempotent**: you can update and re-apply it to safely update the generated components.
- When updating, ensure all new requirements are reflected in the attribute tables and method call instructions.
- Keep the spec clear, concise, and easy to review for both humans and AI.
