# UI List Component Specification Generator

You are tasked with creating a detailed specification for a UI list component based on the uistarter/list-search-starter component pattern. This specification will be used by either AI or UI development teams to implement the component.

## Input Variables
- **[parent-entity]**: The parent entity - used as part of the query for the service call
- **[service-call]**: The service call that will provide the data to be displayed in the list
- **[row-actions]**: Actions that can be performed on individual rows (with row ID)
- **[select-actions]**: Commands to be run on selected elements (if empty, remove checkbox column)

## Component Pattern Reference

The component should follow the structure and styling of the uistarter/list-search-starter component:

### Core Features:
- DHTMLX Grid with pagination
- Search functionality with wildcard support
- Advanced search capability
- Row selection with checkboxes (conditional)
- Drag and drop functionality
- Responsive design with proper styling
- Material Icons for search and advanced search buttons

### Grid Configuration:
- Checkbox column for multi-selection (only if select-actions provided)
- Filterable columns with input filters
- Resizable columns
- Row hover effects
- Selection highlighting
- Pagination with configurable page sizes (10, 20, 50)

## Specification Output Format

Generate a structured specification document with the following sections:

### 1. Component Overview
- Component name and purpose
- Data source description
- Key functionality summary

### 2. Technical Requirements
- Angular component structure
- Required imports and dependencies
- Service integration details
- Interface definitions

### 3. UI Layout Specification
- Header section with title
- Button bar for action buttons
- Search bar with input field and icons
- Grid container with DHTMLX configuration
- Pagination controls

### 4. Data Structure
- Column definitions based on service response
- Field mappings and display names
- Data transformation requirements

### 5. Action Specifications

#### Row Actions Section
- List each row action with:
  - Action name and description
  - Button placement (inline or action menu)
  - Function signature with row ID parameter
  - Visual styling requirements

#### Select Actions Section
- List each select action with:
  - Action name and description
  - Button placement in button bar
  - Function signature with selected IDs array
  - Batch processing requirements
  - Visual styling requirements

### 6. Search Functionality
- Basic search implementation
- Wildcard search support
- Advanced search modal/form requirements
- Search criteria mapping

### 7. Styling Requirements
- CSS class names and structure
- Grid styling specifications
- Button and form element styling
- Responsive design considerations
- Hover and selection states

### 8. Event Handlers
- Search submission handling
- Row action click handlers
- Select action click handlers
- Grid event listeners (drag/drop, selection)

### 9. Error Handling
- Service error handling
- Empty state display
- Loading state management
- Validation requirements

### 10. Testing Considerations
- Unit test requirements
- Integration test scenarios
- User acceptance criteria

## Implementation Notes

1. **Checkbox Column Logic**: If [select-actions] is empty or null, the checkbox column should be removed from the grid configuration.

2. **Action Button Generation**: For select actions, create buttons that pass all selected IDs to the onclick function.

3. **Service Integration**: The component should use the provided [service-call] for data retrieval and any necessary CRUD operations.

4. **Responsive Design**: Ensure the component works well on different screen sizes.

5. **Accessibility**: Include proper ARIA labels and keyboard navigation support.

6. **Performance**: Implement proper data loading and pagination to handle large datasets.
